## Prompt 原文
```
请为一个校园互助服务平台生成完整的需求规格说明书，平台支持学生发布和接单各类互助需求（快递代取、学习辅导、二手交易、组队匹配等），目标用户为大学生。请按 IEEE 830 标准格式输出。
```


## AI 输出摘要
AI 返回了一份结构完整的 IEEE 830 标准需求规格说明书，包含：
- a. 引言（目的、文档约定、读者、范围、参考文献）
- b. 综合描述（产品前景、功能概述、用户类特征、运行环境、设计限制、假设依赖）
- c. 外部接口需求（用户界面、软件接口、通信接口）
- d. 系统特性（8个核心模块的详细功能需求与优先级划分）
- e. 其他非功能需求（性能、安全、质量属性、业务规则、用户文档）
- f. 其他需求（法规合规、运营支持）
- 附录 A 词汇表、B 分析模型占位、C 待确定问题列表

文档按版本管理格式生成，包含修订记录和标准化需求编号。

## Prompt 原文
用户上传了4份定性访谈记录（`访谈笔记_Almira.md`、`访谈笔记_beginner.md`、`访谈笔记_LiOH.md`、`访谈笔记_xujianghu.md`）和1份定量问卷统计表（`软件工程与计算II-问卷.xlsx`），并明确设定了角色——“资深产品需求分析师和用户体验研究员，负责CampusHub高校校园综合服务平台项目”，要求按以下分析框架进行处理：

- 第一步：用户画像与场景还原  
- 第二步：需求分类与提炼（KANO模型视角）  
- 第三步：数据交叉验证  
- 最终输出核心需求概览表、详细用户故事、访谈高频词与金句洞察、下一步产品迭代建议

## AI 输出摘要
AI 返回了一份结构清晰的产品需求文档大纲，严格遵循用户指定的分析框架，具体内容包括：

1. **核心需求概览表**：列出10个需求ID（REQ-001至REQ-010），涵盖实名认证、即时跑腿、信息咨询、二手交易、资金托管、失物招领、激励体系、组队匹配、操作简化、内容审核等维度，并附来源依据及优先级。

2. **详细用户故事**：提供10条符合“作为…我想要…以便于…”格式的用户故事，覆盖从代取快递、课程评价、失物招领、信任建立到成就激励等典型场景。

3. **高频词与金句洞察**：提炼出“顺路/顺手”、“安全/信任”、“麻烦/欠人情”三个高频关键词，并引用三句用户原话以佐证需求真实性与情感倾向。

4. **下一步产品迭代建议**：明确CampusHub V1.0 MVP必须做的3件事（实名认证与资金托管闭环、即时微任务极简流程、结构化信息咨询基础框架）和建议延后做的2件事（复杂社交与搭子匹配、丰富积分商城），并给出理由。

输出内容完整覆盖了用户上传的全部材料，且实现了定性访谈与定量问卷的交叉验证，分析逻辑严密、结论可执行。
